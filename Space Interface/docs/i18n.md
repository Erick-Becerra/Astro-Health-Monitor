# Languages

The whole interface is available in **Spanish** (default) and **English**. The user changes it from the settings button,
and the choice is remembered in the browser under the key `ahm.lang`.

## How it works

| Piece | File |
|---|---|
| Language store (`useLang`, `setLang`, `localeOf`) | `src/shared/lang.js` |
| Translator factory | `src/shared/i18n.js` |
| Hook that returns the translator of the current language | `src/shared/useT.js` |
| Dictionaries | `src/shared/i18n-es.json`, `src/shared/i18n-en.json` |
| Questionnaire texts | `src/lib/questionnaires.js` (English) and `src/lib/questionnaires-es.js` (Spanish) |

A component translates like this:

```jsx
const t = useT();
return <h2>{t.ui("overview")}</h2>;
```

`t.ui("key", { n: 3 })` replaces `{n}` placeholders. Other helpers: `t.system(key, field)`, `t.indicator`, `t.unit`,
`t.card`, `t.gender`, `t.level`, `t.badge`, `t.levelWord`, `t.symptom`, `t.bodyArea`, `t.bodyLabel` and more (see
`i18n.js`). A key that is missing from the dictionary comes back as the key itself, so a new backend value shows up
untranslated instead of breaking the screen.

Dates and numbers use the locale of the language: `es-CL` for Spanish and `en-GB` for English.

## Dictionary structure

Both JSON files have the same groups. The English file must contain every key of the Spanish one.

| Group | Content |
|---|---|
| `levels`, `banners`, `cardStates`, `status`, `levelWords` | Level names and state words |
| `systems` | For each system: `label`, `short`, `description`, `hardware`, `physiology`, `general` (list of tips) |
| `indicators`, `sensorGroups`, `signalQuality`, `sources`, `manualKinds` | Names and units of what the backend sends |
| `cards`, `hazards`, `protocols`, `crewStates`, `gender`, `agencies`, `scenarios` | Names and fixed sentences |
| `symptoms`, `bodyAreas`, `symptomSeverity` | Symptom report |
| `bodyLabels` | Diagram labels and tooltips |
| `ui` | Every other text of the interface |

## Add a text

1. Add the key to `ui` in **both** dictionaries.
2. Use it with `t.ui("yourKey")`.

## Add a language

1. Copy `i18n-en.json` to `i18n-xx.json` and translate it.
2. Add the language to `translators` in `useT.js`, to `LANGS` and `localeOf` in `lang.js`, and accept its code in `read`
   and `setLang`.
3. Add a block for it in `questionnaires-es.js` style and handle it in `localized`, `optionsFor` and
   `safetyMessageFor` in `questionnaires.js`.

## What is not translated

Texts that the backend sends already written, such as the summary of each alert and the recommended steps, arrive in
English and are shown as they are in both languages.

## Clinical texts

The long clinical texts (system descriptions, physiology, general recommendations, protocols) and the Spanish
translation of the questionnaires' treatments and safety message are **drafts**. They must be validated by the clinical
team before any real use.
